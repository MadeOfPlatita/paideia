# Prototipo de puente estructurado offline

El puente `secure_structured_bridge.py` es un ensayo aislado: construye el cuerpo con `build_structured_request`, entrega exactamente esos bytes a `FakeTransport` en memoria, interpreta una respuesta Chat Completions sintética mediante `providers._parse_chat_response`, valida la selección cerrada con el adaptador fake existente y ejecuta `render_selection`. El escenario se pasa exclusivamente al renderizador local en el mismo turno. La salida indica `provider_mode: test_only` y `external_sent: false`; los textos proceden del catálogo editorial local. No hay proveedor real, red, claves, reintentos ni activación de rutas.

La prueba espía compara los bytes completos con el constructor y comprueba el esquema y la ausencia de herramientas, streaming, escenario y perfil como campos de cuerpo. Las pruebas cubren JSON incorrecto y duplicados, rechazo, truncamiento, llamadas a herramientas, 429, fallo TLS simulado, texto o escenario inventados, secreto ficticio y un impostor con método post. Se prueba el cálculo local y la ausencia de reutilización del escenario. La primera prueba se ejecutó antes de crear el módulo y falló por módulo inexistente; luego pasó. Las pruebas negativas adicionales pasaron a la primera, por lo que no se afirma un ciclo rojo individual para cada caso.

Este prototipo no usa ni simula la reserva del ledger, el límite temporal, el singleflight ni la guarda posterior a conexión de la sesión segura. No demuestra compatibilidad con Groq real, calidad semántica del modelo, política de privacidad del texto libre de entrada ni protección frente a código Python hostil capaz de modificar módulos. El escenario y perfil no se añaden como campos separados; el llamante sigue siendo responsable del contenido que coloca en los mensajes.

Integración futura: acordar una interfaz de envío de bytes estructurados que preserve reserva/contabilización, autorización y revocación post-connect de `secure_groq_session.py`, sus límites, singleflight y manejo de credenciales; conectar el parser y validador cerrado sin aceptar proveedores arbitrarios; revisar las restricciones fake-only del servicio y la selección de modo en frontend; pruebas conjuntas de seguridad y carreras, y autorización expresa antes de cualquier conexión real. No se modificaron estos componentes ni se asumió que la sesión existente pueda recibir directamente estos bytes.
